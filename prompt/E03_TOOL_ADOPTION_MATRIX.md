## Firecrawl release-specific cautions and decision

The [official self-host guide](https://docs.firecrawl.dev/contributing/self-host) verifies **v2.11.162**, not an arbitrary latest checkout. A heartbeat alone is insufficient: guide requires a successful actual /v2/scrape. It states no verified minimum host size. Fetch/Playwright default engine paths do **not** provide screenshots/page actions; those require external Fire-engine. Agent/Browser/Interact and specialist formats are not present in the default self-host stack. Therefore a self-host install cannot be presented as Cloud feature parity.

[Pinned v2.11.162 Compose](https://raw.githubusercontent.com/firecrawl/firecrawl/v2.11.162/docker-compose.yaml) includes API/harness, Playwright, Redis, RabbitMQ and NUQ PostgreSQL, plus experimental FoundationDB entries. API and Playwright configured memory limits are8G and4G; these are limits, not measured required RAM. The default publishes API3002, disables DB authentication, and uses unpinned component images such as redis:alpine/rabbitmq:3-management. Optional key/provider/proxy/webhook configuration appears. It provides no ordinary persistent PostgreSQL/Redis/RabbitMQ data volumes. Any evaluation must be private, independently pinned and isolated from Galaxy's main ports/DB/services.

[Pinned search dispatcher](https://raw.githubusercontent.com/firecrawl/firecrawl/v2.11.162/apps/api/src/search/index.ts) chooses Fire-engine when configured, then SearXNG when configured, then DuckDuckGo. Thus SearXNG is optional, and self-host Firecrawl search still forwards public queries externally; it is not an independent search index.
