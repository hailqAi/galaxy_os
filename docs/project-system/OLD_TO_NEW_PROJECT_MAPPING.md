## Current screen and infrastructure findings

- The Project root is a metadata-free server redirect to the implemented Stage 1 landing; it intentionally drops obsolete `workspace` queries.
- The three remaining commercial index return links now target the same canonical Stage 1 landing.
- Stage 2–5 destinations remain disabled until a real backed domain destination is approved; no placeholder stage pages or query-to-route adapter table exists.
- Existing required-document commands cover list/create/update, attach file, submit, decide, mark not applicable, supersede, and history.
- IAM uses explicit permission guards and `BusinessEntityPolicy`; project membership is persisted by `userId`. Existing services still require endpoint-by-endpoint review because frontend hiding is not authorization.
- Existing cross-cutting sources include `FileAsset`, `UploadSession`, `Activity`, `Notification`, `Comment`, `Task`, and `AuditLog`. Approval state currently lives in each business domain rather than one verified generic approval model.

## Migration rule

Prefer adapters, redirects, additive orchestration relations, and computed gates. A data migration is required only for a newly approved field or relation that cannot be derived from existing authoritative records. No existing contract, PO, shipment, inventory, installation, handover, or warranty record is copied into a Project-specific duplicate.
